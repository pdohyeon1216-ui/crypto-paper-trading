# Binance 선물 모의매매

`index.html`을 Microsoft Edge 같은 Chromium 브라우저로 열어 사용합니다. 거래 대상은 Binance Futures의 **BTCUSDT·ETHUSDT·XRPUSDT·DOGEUSDT·SOLUSDT 무기한 선물**입니다. 다섯 종목은 하나의 USDT 모의 계좌와 매매기록을 공유합니다.

화면 오른쪽 위의 **이용 설명서** 버튼을 누르면 프로그램 안에서도 핵심 사용법을 확인할 수 있습니다.

## 핵심 거래 규칙

- 모든 선물 포지션은 **격리 증거금** 방식으로 취급합니다.
- 한 종목에는 진행 중 포지션을 **최대 1개**만 보유할 수 있습니다.
- 같은 종목·같은 방향으로 다시 진입하면 별도 포지션을 만들지 않고 기존 포지션에 합산합니다.
- 같은 종목의 반대 방향 시장가·예약 진입은 기존 포지션을 전량 청산하기 전까지 차단합니다.
- 반대 방향 예약 주문이 기존 포지션과 충돌한 상태에서 체결 조건에 도달하면 두 번째 포지션을 만들지 않고 해당 예약 주문을 취소합니다.
- 이전 버전에서 이미 한 종목에 롱·숏이 함께 저장된 경우에는 데이터를 임의 청산하지 않으며, 한쪽을 전량 청산할 때까지 추가 진입을 제한합니다.

## 종목과 초기 시드

- 화면 상단의 **비트코인·이더리움·리플·도지코인·솔라나** 버튼으로 종목을 전환합니다.
- 우측 상단 **설정**에서 초기 시드를 0.01 USDT 이상으로 입력한 뒤 **초기 시드 적용**을 누릅니다.
- 시드 적용은 USDT 잔고를 입력 금액으로 바꾸며, 모든 종목의 포지션·예약 주문·매매기록을 초기화합니다. 실수 방지를 위해 `초기화` 확인 문구가 필요합니다.

## 차트

- **1분·3분·5분·15분·1시간·4시간** 버튼으로 캔들 주기를 전환할 수 있습니다. Binance Futures REST 캔들과 실시간 Kline·체결 스트림을 함께 사용합니다.
- 차트 위 빈 영역을 좌우로 드래그하거나 **← 이전 / 다음 →** 버튼을 누르면 과거 구간과 최신 구간을 넘겨 볼 수 있습니다. 오른쪽으로 드래그하면 과거로, 왼쪽으로 드래그하면 최신 쪽으로 이동합니다.
- 같은 빈 영역을 위아래로 드래그하거나 **↑ 위 / 아래 ↓** 버튼을 누르면 가격축을 상하로 옮길 수 있습니다. **전체** 버튼을 누르면 좌우·상하 이동이 초기화되고 자동 맞춤 위치로 돌아갑니다.
- 손익비 블럭 내부를 누른 채 드래그하면 시간과 가격 위치를 함께 옮길 수 있습니다. 가로 위치는 블럭이 생성된 시간봉 간격에 맞춰 이동하며, 익절·손절 비율은 유지됩니다.

- 기존 분 단위 EMA와 함께 **10일선**, **30일선**, **50일선**, **100일선**, **200일선**을 체크박스로 켜고 끌 수 있습니다.
- 장기선은 Binance Futures 일봉 종가를 사용하는 단순이동평균(SMA)입니다.
- 분봉에서는 각 시점의 종가를 당일의 실시간 종가로 반영하고, 각 기간에서 하루를 뺀 수만큼의 확정 일봉 종가와 합산해 계산합니다.
- 장기선은 현재가와 거리가 클 때 분봉이 눌리는 것을 막기 위해 기본은 꺼짐이며, 체크하면 차트 가격축에 포함되어 항상 보입니다.

## 매매기록

- 진입 증거금, 부분 청산, 예약 청산 금액은 USDT를 직접 입력합니다.
- 같은 종목·같은 방향이면 진입 레버리지가 달라도 하나의 포지션으로 합쳐집니다. 평균 진입가와 유효 레버리지는 전체 명목가·수량·증거금을 기준으로 다시 계산됩니다.
- 선물 수수료는 진입과 청산에 각각 0.05%씩 고정 적용됩니다(왕복 합계 0.1%).
- 진입과 추가 진입은 통합 포지션의 `entries`에 즉시 저장됩니다.
- 부분청산은 같은 포지션의 진행 중 청산 기록으로 즉시 저장됩니다.
- **매매기록만 삭제**는 완료된 과거 기록만 지우며, 현재 진행 중 포지션의 각 진입·부분청산 기록은 유지합니다.
- 매매기록 맨 위의 **진행 중 포지션** 블록에서 모든 진입·부분청산을 시간순으로 확인할 수 있습니다.
- 전량 청산하면 진행 중 블록이 사라지고, 동일한 기록이 **완료 포지션** 블록으로 자동 전환됩니다.
- 완료 블록에는 전체 수수료·순손익·ROE와 각 진입/청산 이벤트가 보존됩니다.

포지션에 진입하면 평단선과 회색 점선 **손익분기**가 차트 전체 폭의 수평선으로 표시됩니다. 손익 음영은 실제 첫 진입 시점부터 시작하며, 두 라벨은 선을 가리지 않도록 위아래에 배치됩니다.

## 저장과 복구

1. 기본 저장은 브라우저 `localStorage`의 주 저장본과 교대 백업본 두 곳에 체크섬·리비전과 함께 기록됩니다.
2. 저장 뒤 다시 읽어 검증하며, 진입/청산 저장이 실패하면 주문 직전 상태로 되돌립니다.
3. 별도로 IndexedDB에 최신 매매 전용 복구 미러를 유지합니다.
4. **백업 파일 연결**을 한 번 눌러 `futures-trading-backup.json`을 선택하면 파일 핸들을 IndexedDB에 저장·재검증합니다. 연결 직후 실제 JSON 쓰기와 다시 읽기 검증까지 성공해야 `연결·쓰기 검증 완료`로 표시됩니다.
5. 이후 예약매수 생성·체결, 일반 진입·추가 진입, 예약·부분·전량 청산 때마다 같은 파일 하나를 최신 전체 스냅샷으로 자동 갱신하고 체크섬을 검증합니다. 같은 초기화 세대 안의 서로 다른 매매기록만 현재 잔고·진행 중 포지션·주문을 유지한 채 병합합니다. 초기화 이전 세대의 기록은 최신 파일이나 복구 미러에 다시 병합하지 않습니다.
6. 브라우저를 다시 연 뒤 권한 확인이 필요하면 저장된 핸들에 **파일 다시 연결**로 권한만 재승인합니다. 브라우저 보안상 최초 파일 선택과 권한 재승인은 사용자 클릭이 필요합니다.
7. **백업 복원**은 기존 전체 백업과 새 실시간 매매 백업을 모두 읽고 체크섬을 검증합니다.

독립 JSON 파일의 연결·권한 문제는 예약매수 등록·체결, 신규·추가 진입, 수동·부분·전량·예약 청산을 막지 않습니다. 모든 주문과 체결은 먼저 브라우저 이중 저장과 복구 미러에 확정하고, 독립 JSON 파일 저장·재읽기 검증을 직후 실행합니다. 파일 권한이 끊긴 동안의 변경도 같은 최신 전체 스냅샷에 포함되어 재연결 즉시 저장됩니다.

초기화하면 장부 시작 시각이 영구 저장됩니다. 이후 새 매매를 시작해도 이 시각을 지우지 않으므로, 초기화 전에 만들어진 백업 파일이 과거 거래를 다시 살려내지 않습니다. 같은 방향으로 여러 번 진입한 경우에도 각 진입 건은 통합 포지션의 `entries`에 개별 보관됩니다.

브라우저 저장소 두 사본은 브라우저 프로필을 공유하므로, 브라우저 데이터 삭제·프로필 손상에는 함께 영향을 받을 수 있습니다. 독립 JSON 파일 연결까지 완료해야 별도 복구 사본이 생깁니다.

## 폴더 파일

- `index.html`: 화면
- `app.js`: 거래·차트·저장 로직
- `style.css`: 화면 스타일
- `README.md`: 이 설명서
- `futures-trading-backup.json`: 전체 선물 종목의 공용 단일 복구 파일

최초 실행 기본 시드는 **200 USDT**입니다. 이후에는 설정에서 원하는 초기 시드로 변경할 수 있으며, 매매기록은 브라우저 저장키가 유지되는 한 남습니다.
